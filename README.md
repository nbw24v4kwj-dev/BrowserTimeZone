# 浏览器时区控制器（Browser Time Zone）

**简体中文** · [English](README.en.md)

为 Chrome 网页指定一个 IANA 时区，例如 `Asia/Shanghai`、`America/New_York` 或 `Europe/London`。开启时，新网页会使用保存的时区。时区和开关状态保存在当前 Chrome 用户配置中，浏览器重启后继续生效。夏令时会随所选时区和日期自动调整。

支持中文城市搜索、收藏和最近使用、按网站设置时区、页面接口一致性检测、UTC 日期的多时区对照，以及 JSON 设置备份。工具栏的 ON/OFF 表示总开关状态，当前页面的实际结果可在面板中检测。

本项目由 [XOProxy](https://www.xoproxy.com/?utm_source=TimeZonePlugin) 提供支持。XOProxy 是**面向全球业务的住宅代理网络**，提供动态和静态代理。

## 安装与使用

公开仓库主分支仅保留产品与使用说明及历史许可证。[GitHub Releases](https://github.com/nbw24v4kwj-dev/BrowserTimeZone/releases/latest) 提供经过压缩和构建检查的成品安装包。旧源码和包含未压缩代码的旧安装包已下架。GitHub 自动生成的 “Source code” 下载仅包含仓库说明，不能用作扩展安装包。

1. 使用 Chrome 138 或更新版本。从 [GitHub Releases](https://github.com/nbw24v4kwj-dev/BrowserTimeZone/releases/latest) 的 **Assets** 下载 `browser-timezone.zip` 成品安装包，将其解压到固定文件夹。
2. 在地址栏打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择解压后包含 `manifest.json` 的文件夹。
3. 从工具栏的扩展菜单打开「浏览器时区控制器」。首次选择并保存时区会开启时区覆盖。Chrome 的「网站访问权限」决定哪些网页可以应用时区。
4. 关闭「时区覆盖」后，已打开的普通网页会恢复系统时区，已选时区仍会保留。「清除时区」会恢复系统时区并删除该选择。
5. 重新开启或切换时区后，刷新已打开的网页即可应用新设置。

「网站规则」默认按主机名精确匹配 HTTP 和 HTTPS，并忽略端口。勾选「包含所有子域名」后，`antom.com` 的规则同时适用于 `xx.antom.com`、`a.b.antom.com` 等所有层级。范围通过勾选选项设置，现有规则仍保持精确匹配。IP 地址使用精确匹配。

更具体的主机名规则优先。例如，可以给 `antom.com` 及所有子域名设置香港时区，再给 `pay.antom.com` 单独设置系统时区。iframe 按自身主机名匹配规则。未匹配规则的网站使用默认时区，总开关控制全部覆盖。移除子域名规则后，刷新网页即可使用仍匹配的父域名规则；没有匹配规则时使用默认时区。

当前网站有规则时，面板顶部会优先预览规则指定的时区和当地时间，并将该网站的规则编辑区提前显示。默认时区单独标注，仅用于没有匹配规则的网站。保存规则后仍需刷新已打开的网页。

点击已保存规则旁的「编辑」，可修改域名、时区或系统时区模式，以及是否包含所有子域名，再点击「保存修改」更新原规则。「取消编辑」不会保存改动。更改域名时，如果新域名已有规则，面板会提示冲突并保留两条原规则。

输入“纽约”“倫敦”“上海”等城市名也可保存对应时区。最多收藏 12 个时区，最近使用保留 6 个。多时区对照的输入采用 UTC，结果按所选日期计算各地区的时间和夏令时偏移。

默认快捷键为 `Alt+Shift+T` 切换总开关，`Alt+Shift+N` 开启覆盖并选择下一个收藏时区。可在 `chrome://extensions/shortcuts` 修改按键。JSON 导入会先展示预览，点击应用后替换默认时区、网站规则、收藏、历史记录和界面语言。

升级时，把新版文件覆盖到原来的扩展文件夹，再到 `chrome://extensions` 点击「重新加载」。从原目录重新加载会保留保存的时区。升级前已打开的网页需刷新一次，之后可以在原页恢复系统时区。

面板默认跟随 Chrome 的界面语言，支持英文、简体中文、繁体中文、西班牙语、俄语和越南语。其他语言回退至英文。手动选择的语言会保存，可随时切回「跟随 Chrome」。点击面板底部的 XOProxy 支持链接会在新标签页打开官网，网址带有固定的 `utm_source=TimeZonePlugin` 参数。

## 检查是否生效

1. 保存时区并刷新当前网页。
2. 打开插件面板，查看「当前网页」中的目标时区、实际时区和检测结果。
3. 如果提示需要刷新，刷新后点击「重新检测」。出现接口结果不一致时，可将检测结果提交到仓库 Issues。

「查看 iframe 结果」会列出已检测的子文档。无法确认来源的文档会标为无法验证，Worker 不在检测范围内。检测结果反映检测当时的状态，网页刷新或导航后可重新检测。

## 生效范围

扩展会修改获准访问的 HTTP 和 HTTPS 网页的默认 JavaScript 时区，包含同源和跨域 iframe。Chrome 也会按发起方来源匹配 `srcdoc`、`data:`、`blob:` 等关联文档。网页同步读取新建 iframe 的初始 `about:blank` 对象时，仍可能读到系统时区。

Chrome 内置页面、Chrome 网上应用店、Dedicated Worker（包括模块 Worker）、Shared Worker、Service Worker 和 Worklet 使用原有时区。网站显式指定的时区以及按 IP 或账号确定的时区照常生效。少见的非标准日期字符串可能保留 Chrome 的原生解析行为。历史日期的括号内时区名称可能采用 Intl 提供的 GMT 偏移标签。

开启或切换时区后，刷新已打开的网页即可让主文档和子文档使用新设置。刷新前，已打开的文档可能保留旧设置，期间新加载的 iframe 可能已使用新设置。关闭覆盖会恢复已获准访问的活动文档后续创建的格式化对象及日期方法。已有的格式化对象保留创建时的时区。通过浏览器「后退」返回缓存中的网页时，可能需要刷新一次。

扩展使用 Chrome 的内容脚本接口，在匹配文档的网页脚本执行前应用时区。时区脚本随扩展打包，时区和语言偏好保存在当前 Chrome 用户配置中。系统时钟、操作系统时区和已有日期的时间戳保持原值。
